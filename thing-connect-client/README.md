# ThingConnect 微信小程序

本工程使用 Taro、React 和 TypeScript，为 ThingConnect 提供微信小程序客户端。开发者在本目录安装依赖、构建并导入微信开发者工具。服务端部署、设备协议和接口定义分别见[部署指南](../thing-connect/deployment.md)、[设备接入](../thing-connect/device-integration.md)和 [API Reference](../thing-connect/api-reference.md)。

## 功能与边界

| 入口 | 当前行为 |
|---|---|
| 登录 | 邮箱登录、注册、找回密码；人机验证使用网易易盾微信插件 |
| 设备 | 验证码、设备 ID 或扫码绑定；下拉刷新；改名、解绑及查看分场景媒体能力 |
| 实时查看 | 打开服务器提供的播放器 web-view，使用 TiRTC Web SDK |
| 微信通话 | 微信设备授权、小程序呼叫设备、接收设备来电及插件通话页面 |
| 联系人 | 搜索、分类、申请、审批、备注和删除；同账号设备自动关联 |
| AI 角色 | 创建、编辑基础配置、切换和删除；编辑时保留未修改的服务、知识库和工具配置 |
| AI 识别 | 识别类型选择、排序、开关、额度及版本冲突提示 |
| 多人对讲 | 管理设备的房间创建、加入、退出和状态查询 |
| AI 对话记录 | 会话列表分页、文字详情及删除 |
| 我的 | 账号邮箱、修改密码、用户协议、隐私政策和退出登录 |

知识库、MCP、设备插件的管理界面在用户 Web 中使用。AI 对讲和多人对讲的音频连接由设备建立，小程序提供配置与管理入口，不调用设备专用的 AI token 接口。设备的业务互斥和恢复遵循[设备会话模型](../thing-connect/device-session-model.md)。

H5 构建用于页面开发预览，不作为当前交付端。微信授权和通话只能在微信端使用。

## 快速开始

### 前置条件

- Node.js 22.12 或更高版本、npm 10 或更高版本。
- 具备微信 IoT VoIP 能力和易盾插件使用权限的正式小程序 AppID。测试号不能完成设备通话验收。
- 微信 IoT 平台分配的 ModelID，与设备所属型号一致。
- 已部署 ThingConnect 服务，通过同一 HTTPS 地址代理所需的 `/v1/` 业务接口及 `/player` 页面；内部接口不向公网开放。
- 微信后台配置 request 合法域名；实时查看所用 HTTPS 域名配置为 web-view 业务域名。发布和真机验收须启用域名校验。
- 设备按[设备上线流程](../thing-connect/device-integration.md)完成注册、绑定与 MQTT 连接，并上报实际媒体 profile。

### 安装与构建

从仓库根目录执行：

```bash
cd thing-connect-client
npm ci
npm run check
```

`check` 包含类型检查、测试、小程序构建及产物检查。构建时读取同一仓库中的服务端法律文本，因此需要完整检出仓库。

在微信开发者工具中导入 **`thing-connect-client/`**。[project.config.json](project.config.json) 的 `miniprogramRoot` 指向 `dist/weapp/`。把 `appid` 改为自己的正式 AppID；本地工具偏好放在不提交的 `project.private.config.json` 中。

开发时运行：

```bash
npm run dev:weapp
```

构建产物由 Taro 生成，不直接修改 `dist/`。源文件、构建配置和插件声明分别位于 `src/`、[config/index.ts](config/index.ts) 和 [src/app.config.ts](src/app.config.ts)。

### 服务地址与微信参数

以下变量在构建时读取，修改后需要重新构建：

| 变量 | 配置要求 |
|---|---|
| `TARO_APP_API_ORIGIN` | 公网 HTTPS 根地址，不带 `/v1` 或其他路径；小程序缺省为 `https://xiaotai.chat`，自己的部署须显式指定 |
| `TARO_APP_WX_MODEL_ID` | 微信 IoT ModelID；缺省使用示例项目标识，自己的设备须指定实际型号 |

例如在 Bash 中构建：

```bash
TARO_APP_API_ORIGIN=https://api.example.com \
TARO_APP_WX_MODEL_ID=YOUR_MODEL_ID \
npm run build:weapp
```

AppID 和 ModelID 是公开标识。JWT、设备密钥和第三方密钥不写入构建变量或源码。AppID 从微信运行环境读取，不在业务代码中另设一份。

验证码插件与 VoIP 插件的 provider、版本以 [src/app.config.ts](src/app.config.ts) 为准，微信后台需为该 AppID 开通对应插件。服务端启用人机验证时应选择 `yidun`，并配置小程序验证码 ID；具体配置见[部署指南](../thing-connect/deployment.md)。

## 使用流程

1. 注册或登录 ThingConnect 账号。成功登录后本机记住邮箱，退出登录保留邮箱，不保存密码。
2. 添加设备：页面打开时自动聚焦验证码首格；输入设备显示的 6 位验证码、切换到设备 ID 输入，或扫描包含设备 ID 的二维码。
3. 名称为空的设备卡片显示“设置名称”和编辑图标。点击后填写 1–13 个字符的名称，例如“客厅学习机”。已有名称可通过“⋯ → 修改设备名称”编辑。
4. 从设备卡片进入实时查看、微信通话、AI 角色、AI 识别或联系人。更多菜单包含多人对讲、AI 对话记录、通话授权和设备信息。
5. 微信双向通话的准备、重复授权、设备名称与联系人备注的区别见[微信 VoIP 接入](voip.md)。

设备列表首次进入加载数据，不定时轮询，普通返回和切回前台不会自动刷新；下拉可获取最新状态。绑定等显式修改允许更新列表。设备名称和在线状态是读取时的快照，不能据此保证设备一直在线或媒体资源空闲。

设备列表返回后即可浏览和操作，微信授权在后台查询。“确认通话授权”表示授权状态待确认，点击后先检查授权再继续流程；查询失败不视为撤销授权。已知未授权时，主按钮先完成授权，用户再点击发起呼叫。实时查看不依赖微信通话授权。

功能页首次进入可复用当前账号的设备信息快照，业务内容仍从服务端读取。设备绑定、改名和解绑会使快照失效，切换账号隔离缓存。功能页使用各自的刷新入口；服务端始终校验设备归属和业务权限。

联系人备注按设备独立保存。微信联系人备注变化通过 MQTT `callers_update` 通知目标设备重新读取联系人；不是重新申请微信授权，也不会修改其他设备的备注。字段和刷新要求见[联系人通知协议](../thing-connect/api-reference.md#get-v1calldevicecontacts)。

## 二次开发约束

| 位置 | 修改时遵守的边界 |
|---|---|
| `src/pages/`、`src/components/` | 页面交互和展示；通过业务规则及平台适配调用微信能力 |
| `src/domain/` | 媒体场景判断、业务数据与校验；`stream`、`voip`、`call` 能力分开处理 |
| `src/services/` | HTTP、登录状态、设备信息快照与显式变更通知 |
| `src/hooks/device-workspace.ts` | 功能页的设备上下文、操作互斥和卸载后的响应隔离 |
| `src/platform/media.weapp.ts`、`src/platform/voip/` | 微信插件生命周期、来电参数解析及视频配置 |
| `src/platform/captcha.weapp.tsx`、`src/native/captcha/` | 易盾原生组件桥接及验证生命周期 |
| `scripts/prepare-assets.cjs` | 从服务端法律页面提取正文，并生成内嵌登录头像；`src/generated/` 不提交 |

共享页面不直接调用微信插件，不使用浏览器 DOM API。所有业务 HTTP 请求经过 `services/api.ts`：同时检查 HTTP 状态和数值业务码，VoIP 接口成功码为 `0`，其他业务接口通常为 `200`；不按错误文案判断业务分支。

用户 JWT 代表 ThingConnect 账号及其设备权限；微信 OpenID 由 `wx.login` 经业务服务端换取，代表当前微信身份。不能用 OpenID 替代用户鉴权，也不能用用户 JWT 调用设备 token 接口。

播放器入口验证设备归属和在线状态后，将 JWT 放入 URL fragment。不得改为 query 参数、日志或分享链接；播放器与服务器页面需保持协议兼容。

## 检查与验收

日常修改在本目录执行 `npm run check`。视频配置测试覆盖双向 caller/listener 映射、旋转、镜像、`contain/fill`、入呼 query 及 profile 缓存回退。通话和页面测试覆盖重复点击、旧房间事件、失败清理、慢授权、账号切换及设备快照失效。

产物预算为 1.5 MiB，登录头像不超过 64 KiB；构建脚本校验预算、页面及插件声明。实际预览包大小以微信开发者工具为准。

开发者工具应验收登录、设备绑定、未命名入口、名称校验、改名保存、联系人操作、页面返回、网络失败和 JWT 过期。修改页面生命周期时检查返回和切回前台是否产生额外请求。

真机验收必须覆盖：

- 易盾首次弹窗、取消、重试和验证码校验。
- 首次授权、已授权重复操作、关闭后恢复及授权记录清空后的授权。
- 双向纯音频、单向视频和双向视频，设备来电的前台、后台及冷启动路径。
- 旋转、镜像和横竖屏素材的 `contain/fill`；设备编码方向单独验证。
- 取消、拒接、占线、无人接听、双方挂断、断网和弱网恢复；结束后可以再次呼叫。
- 播放器域名、摄像头/麦克风权限、账号切换和过期登录。

自动测试和构建通过不代表微信插件、硬件及媒体链路通过。记录验收结果时分别列出通过、失败、跳过及缺失的外部条件。

## 问题排查

| 症状 | 检查与处理 |
|---|---|
| 登录后接口返回 401 | 重新登录；确认构建地址及代理路由正确，不把日志中的 JWT 发给他人 |
| 设备列表为空或状态过期 | 检查设备绑定的 ThingConnect 账号，确认 MQTT 在线后下拉刷新 |
| 验证控件未就绪或构建提示验证码组件路径 | 确认正式 AppID 的易盾权限、插件声明和验证码 ID；检查原生桥接组件是否进入产物，再用真机验证首次弹窗 |
| 实时查看无法打开 | 检查 HTTPS 证书、web-view 业务域名、`/player` 路由、设备归属与在线状态 |
| 设备改名后微信来电名称仍是原名 | 业务名称与微信授权名称是不同状态；按 [VoIP 名称规则](voip.md#设备名称与联系人备注)处理，不能把重复调用授权接口当作名称覆盖接口 |
| 授权、通话或画面异常 | 按 [VoIP 排查表](voip.md#问题排查)核对微信状态、业务授权关系、插件版本与设备 profile |

H5 页面开发可运行 `npm run build:h5`，产物在 `dist/h5/`。默认接口使用同源 `/v1/`，预览服务器需要配置代理；普通静态服务器不具备接口转发能力。显式使用跨域地址时需由服务端配置 CORS。
