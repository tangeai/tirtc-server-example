# ThingConnect Admin Server

`admin-server` 提供 Admin Web、管理员认证与 MFA、RBAC、用户和设备管理、动态配置、数据字典、服务状态、任务中心和审计日志，默认监听 `9000`。

整套系统的环境准备、首次安装、Supervisor、Nginx、数据库迁移、验收、更新和恢复步骤见 [ThingConnect 部署指南](../../deployment.md)。下面只说明 Admin Server 自身的使用约束。

## 启动配置

启动配置示例位于 [config.yaml.example](config.yaml.example)，只包含进程启动必需项：

- HTTP 端口和可信代理。
- MySQL 运行账号 DSN，以及可选的 `database.max_open_conns` / `database.max_idle_conns` 连接池限制；修改后重启，容量预算见部署指南。
- Redis 地址、密码和 DB。
- 所有已安装服务共享的 `internal.key`。
- 独立的 `admin.jwt_secret`。
- MFA 数据使用的 `security.config_encryption_key`。
- Admin 任务文件目录。

公开示例中的 `replace-with-*` 和 `your-*` 是不可运行的占位值。生产首次安装应由 Web 安装器生成正式配置和共享密钥，不要手工复制示例密钥。

`security.config_encryption_key` 是 Base64 编码的 32 字节随机值，用于管理员 MFA 因子和旧版配置密钥迁移。不能直接覆盖已有实例的密钥，否则已有加密数据无法读取。

## 管理员初始化

首次 Web 安装会创建首个管理员、默认菜单、权限以及以下角色：

- 超级管理员。
- 运营管理员。
- 技术支持。
- 审计员。

手工配置部署使用 `deploy-prod.sh init-admin`。数据库已有管理员时，该命令拒绝重复初始化。管理员密码至少 8 位，且必须包含英文大写字母、英文小写字母和数字；允许同时使用中文和特殊字符。首次登录后按安全策略修改密码并绑定 TOTP。

新增或修改管理员、调整角色权限、撤销会话和重置他人 MFA 属于高风险操作。启用 MFA 时，提交此类操作需要当前登录管理员自己的 TOTP 验证码或恢复码，不是被编辑管理员的验证码。恢复码验证成功后立即失效。

## 动态配置

Admin 配置中心管理 `device-server`、`user-server`、`voip-server`、`ai-server`、`call-server`、`recognition-server`、`common` 和 `system` 命名空间。

- 数据库没有发布值时使用后端注册表默认值。
- 普通业务配置不读取服务 YAML 中的同名旧业务值；`web.language`、`web.site` 的本地回退规则分别见下方“用户页面语言”和“官网名称与开发板”。
- TiRTC App ID、Access Key ID 和 Secret Key ID 没有可运行默认值，后台将其标记为必填阻塞项。
- User、VoIP、Call 的 `mqtt.connection` 没有可运行默认值，三个服务分别发布独立账号。Admin、Device 和 AI 不连接 MQTT。
- MQTT 表单可以先用尚未发布的值测试 Broker 网络、TLS 和账号认证；发布接口也会自动复检，失败时保持原配置不变。固定 ClientID 测试使用临时连接 ID，不会断开同名业务客户端；服务器启动预检再使用正式 ClientID 做最终检查。
- User、VoIP、AI、Call 首次启动必须从 Admin 取得有效 TiRTC 配置；需要 MQTT 的服务还必须取得有效 MQTT 配置。Admin 不可达或响应无效时拒绝监听。
- 普通配置在运行期热加载；MQTT 和 TiRTC 的 `reload` 为 `restart`，发布后通过服务器进程管理命令重启对应服务。
- 运行期间 Admin 短暂不可达时，业务服务继续使用内存中的最后有效值并重试。

普通字段和密钥字段都以明文 JSON 存储在 MySQL。Admin Web 对密钥使用密码控件，默认显示 `*`；具备相应权限的管理员可点击眼睛查看原值。数据库账号、备份、网络和审计必须覆盖这些明文凭据。

内置配置使用中文表单。扩展配置时，应同时在后端注册表登记中文名称、说明、默认值、必填/阻塞属性、密钥路径、字段定义和校验规则；否则页面只提供“高级配置”JSON 编辑入口。

## 设备池任务

“业务管理 → 设备管理 → 设备池”支持 CSV 导入。文件要求：

- UTF-8 或带 BOM 的 UTF-8。
- 固定表头和顺序：`device_id,device_key`。
- `device_id`、`device_key` 必填且不超过 64 个字符。
- 单个文件不超过 10 MB、10 万行。
- 每个设备 ID 只能导入一次。

```csv
device_id,device_key
TC-DEVICE-000001,replace-with-device-secret
```

导入后在“运维审计 → 任务中心”查看逐行结果。失败或部分成功的任务可以重试并下载结果 CSV。设备密钥不在设备池列表中展示。

## 健康检查与排障

- `/health/live`：只表示 Admin 进程存活。
- `/health/ready`：检查 MySQL、Redis 和 Admin 数据库迁移版本。

首次安装页面持续显示结构化失败原因和处理建议。MySQL 预检分别验证迁移账号连接和运行账号登录；运行账号失败时按页面检查密码、账号锁定、TLS、MySQL 实际识别的来源 Host 及目标库 DML 授权。Redis 失败时检查地址、认证、DB 编号、防火墙和监听地址。客户可见响应不包含 SQL、Redis、MQTT 客户端原始错误、内网连接串或凭据，详细原因只进入受保护的服务日志。

首次安装只启动 Admin，并为六个业务服务生成基础配置。Admin 不执行主机进程命令。服务状态页展示六个业务服务的版本、提交号、依赖状态、配置 revision、缺少的阻断配置和可复制的服务器启动或重启命令。

服务器上的 `service-local.sh` 在业务服务启动前运行 Admin 只读预检，检查基础配置、阻断动态配置、MySQL schema、Redis 和对应 MQTT 账号。失败时服务保持停止，终端显示可操作建议。预检不执行数据库迁移或数据修改。

常见检查：

- 页面刷新后无法登录：确认 HTTPS 环境使用安全 Cookie，本机 HTTP 开发关闭安全 Cookie。
- 登录后没有导航：确认首个管理员初始化成功，并重启 Admin 重新加载权限。
- 页面显示的客户端 IP 是代理地址：只配置真实代理 IP/CIDR，并确认代理传递 `X-Forwarded-For`。
- 业务服务离线：检查各服务到 Redis、Admin 的网络，以及所有已安装服务的 `internal.key` 是否一致。
- 动态配置未生效：检查配置是否已经发布、目标实例是否在线及其配置 revision。

接口契约见 [Admin API](API.md)，业务接口见 [API Reference](../../api-reference.md)。

## 官网名称与开发板

在“服务配置 → 用户服务 → 站点名称”发布 `web.site`。`name` 为站点名称，`name_en` 为英文名称（留空沿用站点名称），最多各 40 个字符；`public_url` 填写正式站点的 HTTPS 根地址，例如 `https://example.com`。首页和开发板页的导航、标题、分享信息与结构化数据使用此配置，下次打开页面生效。配置不含密钥，沿用配置发布权限、审计和实例 revision。

未发布（revision 为 0）时使用 user-server YAML 的 `web.site`，省略时使用“探鸽 · 小钛”。Admin 暂时不可达时保留最后有效配置，启动依赖保持不变。未填写正式网址时不输出 canonical，`/sitemap.xml` 返回 404；填写后可提交该站点地图到搜索平台。

首页按后台排序显示前三块已上架开发板，固件和烧录指南直接使用各条目中的链接；无资源链接时不显示对应按钮。更多条目在 `/boards` 查看。产品图片、能力标签、适配状态和资源链接在“开发板目录”维护。

## 用户页面语言

在用户服务、AI 服务和呼叫服务的配置页分别编辑 `web.language`：默认语言选择“跟随浏览器”“简体中文”或“English”，并设置是否允许用户切换。海外站将三个服务都设为 English。各服务独立读取配置，发布后下次打开对应页面使用该版本；已打开的页面保留当前语言和操作状态。

允许切换时，同一站点的浏览器优先使用用户手动选择的语言；禁止切换时，使用本服务的默认语言。“跟随浏览器”对中文浏览器使用简体中文，其他浏览器使用英文。登录、注册和退出保留语言选择。

`web.language` 没有发布值（revision 为 0）时，各服务使用自己的 `config.yaml` 中的 `web.language`；省略 YAML 配置时，默认跟随浏览器且允许切换。服务启动仍需要可用的 Admin；运行期间 Admin 暂时不可达时保留最后有效配置。语言值不含密钥，使用现有配置权限、发布审计和实例 revision 查看生效状态。

界面语言只影响页面文案和操作提示，设备名称、用户填写的提示词、AI 对话及云端资源内容保持原文。邮件模板和第三方验证码按各自配置管理。Admin 管理页面使用中文。

## AI 角色类型

在“服务配置 → AI 服务 → 角色类型”维护类型名称、角色音色、默认提示词和展示排序。新增记录先保存为草稿，选择可用音色后启用；停用后不出现在用户可选目录中。编辑及启停操作需要填写原因，记录进入审计日志。音色旁的试听只播放样音。

Admin 数据库迁移包含 58 条中文默认目录资料。普通话正式预设中具有明确音色对应关系的条目使用 `cosyvoice-v3-flash` 或 `seed-tts-2.0`；目录区分相同 ID、同系列版本和风格替代；风格替代在后台单独标注。未选定音色或缺少提示词的条目标记为未启用。来源没有提供提示词的记录保持为空，补齐提示词和可用音色后才可启用。目录页显示总数、启用数量、缺少音色及提示词数量，并支持语言筛选。

模型和音色必须成对匹配探鸽实时目录。`ve-bidirection` 可以保留关联资料，但当前角色编辑器没有该模型的调用适配，不能启用。不同模型没有试听地址时显示“暂无试听音频”。默认资料迁移只更新未被管理员修改的初始记录，重复执行保留管理员修改；名称冲突时保留现有记录。通过正常部署执行 Admin 迁移后再启动服务，运行账号无需 DDL 权限。

用户端添加和编辑使用同一配置界面，长提示词在文本框内滚动，底部提供保存操作；描述和开场白位于“扩展能力 → 更多角色信息”。用户端通过角色类型选择声音，不提供单独更换音色的入口；语音设置展示当前声音及试听，并可通过三档滑块选择回复速度（慢、标准、快）和回复音调（低、标准、高）。选择类型时复制音色和提示词到自己的角色草稿；已有手动设定可以保留或替换，保存后独立于模板。管理员修改模板不会批量改写已有用户角色。读取与编辑权限分别为 `ai_role_type.read`、`ai_role_type.write`，除 AI 服务菜单访问权限外，需在管理员角色中分别授权。

用户端“模型与记忆”可选择 `qwen3.5-flash`、`qwen3.7-flash`、`qwen3.7-plus` 和 `doubao-seed-2-0-mini-260428`，或沿用基础配置。千问使用 `ali-llm`，豆包使用 `doubao`；切换厂商时使用目标厂商的系统账号配置，原厂商的自定义连接凭据不带入新厂商。

角色类型绑定 TTS 模型、音色及默认提示词，支持 `cosyvoice-v3`、`cosyvoice-v3-flash` 和 `seed-tts-2.0`，可选音色以探鸽实际返回的模型与音色 ID 组合为准。云端未提供某个模型的音色时，不能借用其他模型的同名音色启用类型。用户的大模型独立选择，切换角色类型保留已选大模型。

## 查看设备上报属性

进入“设备管理”，在“用户设备”列表点击“详情与上报属性”。详情显示芯片、开发板和固件版本；“设备上报属性”按实时音视频、设备通话、微信通话分栏展示有效能力字段，可展开查看对应 JSON。不需要先完成微信设备授权。未上报的场景显示空态，离线设备仍可查看已保存的上报信息；此页面读取需要 `device.read` 权限。
