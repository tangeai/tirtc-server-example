# API 错误响应规范

本文约定 device-server、user-server、ai-server、call-server 和
voip-server 的对外错误处理方式。单纯优化错误说明时，已有客户端可以
继续按原有 `code` 处理，不需要因 `msg` 变化而修改业务分支。

## 兼容性规则

1. 仅修改 `msg` 时，不改变已发布的业务错误码、HTTP 状态和 JSON 字段。
2. 客户端只允许根据 `code` 判断业务流程，不得根据 `msg` 文本分支。
3. `msg` 使用简体中文；字段名、协议名和常用缩写可以保留原文，例如
   `device_id`、`Nonce`、`MQTT`、`VoIP`。
4. 成功响应中的既有 `msg` 保持兼容，不属于本规范的翻译范围。

业务码存在历史语义错误时，可以进行单独的接口语义纠正，但必须同步更新
API 文档和客户端分支。例如 VoIP/Call 接口过去把设备解绑、微信授权失效
或资源权限错误混用为 `401`，现已分别使用 `6006`、`40205`、`40300`
等业务码；只有 JWT 登录凭证失败继续使用 `code=401`。这类修改不属于
单纯的文案优化。旧码到新码的客户端迁移表见
[API Reference「近期错误码迁移」](api-reference.md#近期错误码迁移)。

## 错误说明的粒度

同一错误码可以按实际失败阶段返回不同 `msg`。例如：

| `code` | 失败阶段 | 示例 `msg` |
|---|---|---|
| 6008 | 时间戳格式错误 | `签名校验失败：时间戳格式错误，应使用 Unix 秒级时间戳` |
| 6008 | 设备时钟过慢 | `签名校验失败：设备时间戳早于服务器时间超过 300 秒，请校准设备时钟` |
| 6008 | 设备时钟过快 | `签名校验失败：设备时间戳晚于服务器时间超过 300 秒，请校准设备时钟` |
| 6008 | Nonce 重放 | `签名校验失败：Nonce 已使用，请重新生成随机 Nonce 后重试` |
| 6002 | 签名上报证明过期 | `设备离线：设备签名上报记录不存在或已过期，请重新上报` |
| 6002 | 临时 MQTT 断线 | `设备离线：设备临时 MQTT 连接已断开，请重新连接后重试` |
| 5001 | MQTT 发布失败 | `MQTT消息下发超时：MQTT 消息发布失败，请稍后重试` |
| 5001 | 设备未确认 | `MQTT消息下发超时：设备未在规定时间内确认授权消息，请保持连接后重试` |
| 50200 | AI 上游失败 | `创建角色失败：AI 云服务暂不可用，请稍后重试` |

这样既保持错误码兼容，也能让设备日志、客户端提示和现场排查明确指出失败阶段。

## 安全边界

以下内容只写服务端日志，不返回给客户端：

- SQL、Redis、MQTT 客户端和第三方 SDK 的原始错误；
- 内网主机名、端口、查询语句、堆栈和密钥相关信息；
- 微信、AI 云服务返回的未审查原始文案；
- 可能帮助枚举账号、设备或凭证的详细校验结果。

内部错误统一对外返回 `服务器内部错误，请稍后重试`，日志通过
`request_id` 关联。签名错误中，时间格式、时间偏差、请求头缺失和
Nonce 重放可以对外说明；未知设备、密钥错误和 HMAC 不匹配仍使用
较笼统的签名失败说明，避免泄露凭证校验细节。

## 实现要求

- 服务层用包装错误保留父错误，例如详细的 MQTT ACK 超时错误仍包装
  原有 5001 错误，因此 `errors.Is` 和错误码映射保持不变。
- Handler 的 JSON 解析/字段类型错误使用稳定中文说明，原始验证库错误写日志。
- `50000`、未映射错误和上游 SDK 错误必须经过统一响应函数清洗。
- 新增或调整失败路径时，应同时测试：错误码符合 API 文档、HTTP 状态
  符合服务约定、中文 `msg` 可操作、原始错误未出现在响应中。

## 设备端参考

嵌入式设备保存并上报数值 `code`，把 `msg` 作为诊断文本记录即可。
不要比较中文字符串，也不要假定同一个 `code` 永远只有一个 `msg`。
Linux C、Python 和 ESP32 示例均按这一规则读取服务端 `msg`；如果
响应没有有效 `msg`，才使用本地兜底说明。
